## Figure 1. Source-to-inference signal chain

- **Communication objective:** orient the reader to the manuscript's central inverse-problem framing in one image — a source state passing through excretion, sewer transport, sampling, and analysis to become a measured concentration, with the "recoverability" question sitting at the center.
- **Visual hierarchy:** a single horizontal pipeline (source state → sewer-entry load → in-transit signal → sampled/measured signal → reconstructed estimate → decision), with the three distortion categories (amplitude, temporal, spatial) shown as recurring labels attached to each pipeline stage where they act, not as a separate legend disconnected from the pipeline.
- **Structural layout sketch (text form):**
  - Panel A (full width, top): six labeled boxes in a horizontal row — *Source state* → *Sewer-entry load* → *In-transit signal* → *Sampled signal* → *Measured/analyzed signal* → *Reconstructed estimate* — connected by rightward arrows.
  - Below each arrow, a small color-coded tag naming which distortion category (amplitude / temporal / spatial, three fixed colors used consistently across all four figures) acts at that transition, per §1.1-§5's actual stage attributions.
  - A dashed bracket beneath the *Sampled signal → Reconstructed estimate* arrow, labeled "identifiability check" (§5.2), pointing to a small branch: one path labeled "identifiable → proceed," one labeled "non-identifiable → flag, do not report a point estimate" (§5.2's core judgment).
  - Panel B (small inset, bottom right): the three distortion-category definitions (amplitude/temporal/spatial, §1.1) as a compact three-line legend, not a separate figure.
- **Draft caption (draft, not final):** "Figure 1. The wastewater signal chain as an inverse problem. A source-end population state (infection, consumption, or exposure status) is transformed through excretion, sewer transport, sampling, and analysis before being measured; each transition can introduce amplitude, temporal, or spatial distortion (§1.1). Recovering the source state from the measured signal is possible only where the resulting inverse problem remains identifiable (§5.2); where it is not, this review argues a point estimate should not be reported. Distortion-category attributions per transition follow this review's own taxonomy (§1.1-§5), not a single external source."
- **Elements flagged "pending evidence verification":** none currently — every element is this review's own structural/propositional framework (the pipeline stages, the three-category taxonomy, and the identifiability branch-point are all explicitly self-attributed in the caption draft above). **If a future version annotates any pipeline stage with a specific study's quantitative distortion magnitude** (e.g., "typically X% signal loss at this stage"), that annotation must be added only after the underlying study passes full-text verification, and must itself be tagged pending evidence verification until then.
- **Source sections:** §1.1, §2, §3, §4, §5.
- **Potential copyright issues:** none anticipated — original schematic.

## Figure 2. Amplitude-temporal-spatial distortion framework

- **Communication objective:** make the three-term distortion taxonomy (§1.1) visually explicit as a classification device.
- **Visual hierarchy:** three parallel columns (amplitude / temporal / spatial), each populated with named mechanisms already in the manuscript text.
- **Structural layout sketch (text form):**
  - Three vertical columns, headed "Amplitude," "Temporal," "Spatial" (same three fixed colors as Figure 1).
  - Each column lists 3-4 mechanism examples as stacked labeled boxes, with a small section-number tag next to each (e.g., "dilution [§3.4]," "sewer-biofilm decay [§3.2]," "recovery loss [§4.1]" under Amplitude; "shedding kinetics [§2]," "retention-time distribution [§3.1]," "sampling-schedule mismatch [§4.1]" under Temporal; "heterogeneous flow paths [§3.1]," "combined-sewer overflow [§3.4]," "differential storm response [§3.4]" under Spatial).
  - No arrows between columns — this is explicitly a classification diagram, not a process diagram (Figure 1 already covers process/sequence).
  - A thin horizontal band beneath all three columns, labeled "these three categories are not mutually exclusive within a single event (§3.5)" — reflecting §3.5's point that rainfall perturbs amplitude, temporal, and spatial dimensions simultaneously.
- **Draft caption (draft, not final):** "Figure 2. A three-category taxonomy for wastewater signal distortion. Every distortion mechanism identified in this review — from source-end shedding heterogeneity through sewer transport to sampling and analysis — is classified as amplitude, temporal, or spatial distortion, or some combination of the three (§1.1, §3.5). This taxonomy is this review's own organizing framework (§1.3); individual mechanism examples are drawn from the sections indicated, some already reported in the literature (e.g., sewer-biofilm decay, §3.2) and some noted here as structurally implied by the framework rather than independently evidenced."
- **Elements flagged "pending evidence verification":** the specific mechanism-to-category assignments that rest on a single cited study (e.g., "sewer-biofilm decay" under Amplitude, sourced from Zhang et al. 2023 / Jung et al. 2026, both currently abstract-checked only, per `WBE_Review_Critical_Claim_Verification_Queue.csv` row P3-3) should carry a visual marker (e.g., a small "†" superscript with a caption footnote: "† mechanism direction reported in cited literature, not yet full-text verified — see Critical Claim Verification Queue") until that claim resolves. Purely definitional/structural elements (the taxonomy itself, the three category names) need no such marker, since they are this review's own framework, not an empirical finding.
- **Source sections:** §1.1, §2, §3.2-§3.4.
- **Potential copyright issues:** none anticipated.

## Figure 3. Process-informed reconstruction and uncertainty framework

- **Communication objective:** show how identifiability, observability, validation level, and uncertainty propagation relate to each other within the reconstruction process (§5).
- **Visual hierarchy:** a decision-flow structure ending at "defensible inference" (§5.5).
- **Structural layout sketch (text form):**
  - Top node: "Select inferential target" (§5.1), branching to the six named targets (trend, relative change, anomaly, absolute load, prevalence/incidence/consumption/exposure) as a small fan-out, not individually elaborated.
  - Second row: "Choose model family accordingly" (§5.1), a single box (the six-family list lives in Table 3, not duplicated in the figure, to avoid redundancy per the Table Design Brief's redundancy check).
  - Third row: a diamond decision node "Identifiability/observability checked? (§5.2)" with two exits: "Yes → proceed" and "No / equifinality present → flag, narrow claim, or seek informative data design" — directly encoding §5.2's core judgment ("a model may fit the observations while the target state remains non-identifiable").
  - Fourth row: "Match validation level to target" (§5.3), a single box with a small side-list of the six validation levels in shrinking-confidence order (internal fit → temporal holdout → external site → event-based → synthetic-state recovery → decision-value), explicitly ranked as *evidentiary strength for the identifiability/observability question*, not as a general quality ranking independent of target.
  - Fifth row: "Propagate uncertainty" (§5.4), one box, with a compact side-annotation listing the seven input-uncertainty categories as small icons/labels rather than expanded text.
  - Final node: "Defensible inference" (§5.5), reached only if a calibrated-coverage check and a decision-threshold-appropriateness check both pass; otherwise routed to "disclose wide interval / qualitative statement only" (§5.5's explicit fallback).
- **Draft caption (draft, not final):** "Figure 3. From inferential target to defensible inference. This review's proposed decision sequence for reconstruction (§5): the inferential target determines the appropriate model family (Table 3); identifiability and observability must be checked, not assumed from fit quality alone (§5.2); the validation level actually achieved must match, not exceed, what is claimed (§5.3); uncertainty is propagated across all relevant input sources (§5.4); and a reported interval is defensible only once its coverage and decision-relevance have themselves been checked (§5.5). This is this review's own proposed framework, not a validated protocol independently confirmed in the cited literature."
- **Elements flagged "pending evidence verification":** the validation-level ranking's *general applicability* (i.e., whether the six-level ordering used here matches how validation is actually practiced across the cited studies) is itself part of Table 3's evidence-classification task (see Task #113/Table Design Brief) — if Table 3's per-model-family "minimum validation" cells change after full-text verification, this figure's validation-level side-list should be re-checked for consistency, though the ordering itself (internal fit is weaker evidence than external site validation) is a definitional/methodological point, not an empirical finding requiring citation.
- **Source sections:** §5.1-§5.5.
- **Potential copyright issues:** none anticipated — replaces/merges the source draft's prior Figure 2/Figure 3.

## Figure 4. Detection-to-decision readiness pathway

- **Communication objective:** consolidate the normalization decision logic (§4.4), the four actionability conditions (§6.3), and the five-level technology-readiness hierarchy (§7.3) into one pathway.
- **Visual hierarchy:** a staged ladder/funnel, bottom to top, five rungs matching §7.3's hierarchy.
- **Structural layout sketch (text form):**
  - Five stacked horizontal bands, bottom to top: *Analytical detection* → *Field validation* → *Cross-site validation* → *Operational integration* → *Demonstrated decision value* (verbatim from §7.3).
  - At the boundary between each pair of adjacent bands, a small "gate" icon labeled with the specific condition that must be met to advance — for the *Field validation → Cross-site validation* gate specifically, label it with §5.3's "external site validation" definition, to keep this figure's readiness language consistent with Figure 3's validation-level language (a cross-figure consistency check, not a new claim).
  - A horizontal side-track, aligned with the *Analytical detection* through *Operational integration* bands, listing §6.3's four actionability conditions (uncertainty translated to decision-relevant terms; named institutional actor/protocol exists; detection-to-action interval shorter than the condition's own timescale; alert validated against its specific deployment's cost structure) as a checklist a signal must clear in parallel with climbing the ladder, not sequentially after it.
  - A callout box beside the *Demonstrated decision value* band, quoting §7.3's core proposition verbatim: "Analytical novelty is not equivalent to epidemiological validity, operational readiness, or demonstrated decision value."
  - **No specific named technology (digital twins, passive samplers, a specific ML model, etc.) is placed at a specific rung in this design.** This is a deliberate choice, not an oversight — placing a real, named technology at a specific readiness level is exactly the kind of claim that needs full-text-verified evidence about that technology's actual demonstrated validation level, which this review has not yet completed for any of §7.1-§7.2's cited examples.
- **Draft caption (draft, not final):** "Figure 4. A proposed readiness hierarchy for wastewater-based surveillance signals, from analytical detection to demonstrated decision value (§7.3), integrated with the four conditions this review argues govern whether a scientifically valid signal is actually actionable (§6.3). A favorable result at one level is evidence for that level only, not for the levels above it (§7.3). This hierarchy is this review's own proposed framework; it does not itself rank any specific named technology, study, or deployment — such placements would require full-text-verified evidence of that technology's demonstrated validation level and are deliberately omitted here pending that verification."
- **Elements flagged "pending evidence verification":** explicitly and pre-emptively, **any future addition placing a specific named technology, study, or deployment at a specific rung of this ladder** must be tagged pending evidence verification until the underlying source clears full-text review — this is the figure most likely to accumulate exactly this kind of claim over time, so the constraint is stated here prominently rather than left implicit.
- **Source sections:** §4.4, §6.3, §7.3.
- **Potential copyright issues:** none anticipated.

## Cross-figure consistency notes

- All four figures use the same three-color coding for amplitude/temporal/spatial distortion (Figures 1 and 2 use it directly; Figures 3 and 4 do not need it but should avoid reusing those three colors for unrelated elements, to prevent a reader misreading an unrelated color-coded element as a distortion-category reference).
- Figure 3's validation-level list and Figure 4's readiness-hierarchy gates should use identical terminology for "external/cross-site validation" (currently drafted consistently above) — this was checked directly against §5.3 and §7.3's actual wording during this drafting pass.
- None of the four draft captions above states a specific quantitative figure, a specific study's finding, or a cross-study performance ranking. Every reference to "this review's own framework/proposition" is deliberate and should be preserved in any later revision — removing that self-attribution language would turn a propositional claim into an implied empirical one, which is exactly the overextension risk this project's standing discipline exists to prevent.
